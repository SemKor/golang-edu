# Урок 3 - Конкурентность. Горутины и способы их синхронизации.

Одним из приемуществ языка Golang часто отмечают его реализацию работы с конкурентными задачами.</br>
Наряду с простым синтаксисом мы также имеем понятные средства для организации взаимодействия между потоками исполнения программы.</br>
Функцией (потоком), выполняющейся конкурентно по отношению к другим функциям программы, называется <b>горутина (goroutine)</b>.</br>
Когда мы запускаем любую нашу программу (go run main.go), рантайм выделяет под неё <b>"main"-горутину</b>,</br>
в которой исполняется весь программный код, расположенный в main функции, и все ее вызовы функций вниз по стэку.</br>
Если мы хотим запустить еще одну функцию, которая должна исполнить себя конкурентно нашей main-горутине, то мы, всего лишь, должны написать:</br>

```go
package main

import "fmt"

func main() {
	// какой то код до
	go func() {
		fmt.Println("hello from goroutine!")
	}()
	fmt.Println("hello from main!")
	// какой то код после
}
```
Но что же будет если мы исполним данный фрагмент? </br>
Мы увидим только - "hello from main!"</br>
Произойдет это потому, что планировщик (scheduler) не успеет передать управление "дочерней" горутине и</br>
он просто выйдет из main-функции исполнив ее до конца.</br> Что же делать в такой ситуации?</br>
Тут для нас разработчики языка сделали два инструмента для синхронизации работы горутин - <b>каналы (chan)</b> и <b>группы ожидания (WaitGroup)</b>.</br>
1) **sync.WaitGroup** - структура пакета sync, которая позволяет определить группу горутин,</br>
   которые, в свою очередь, должны выполняться вместе как одна группа.</br>
   А значит, можно установить блокировку, которая приостановит выполнение функции, пока не завершит выполнение вся группа горутин. </br>
   Итак, изменим наш пример, чтобы он выполнился согласно нашим ожиданиям - мы хотим увидеть в stdout две записи:</br>
   hello from goroutine!</br>
   hello from main!</br>

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	// какой то код до
	wg := sync.WaitGroup{} // создадим экземпляр группы
	wg.Add(1)              // зададим кол-во рутин, которых нам необходимо дождаться
	go func() {
		fmt.Println("hello from goroutine!")
		wg.Done() // сообщим группе о том, что рутина закончила исплнение
	}()
	wg.Wait() // заблокируем main-горутину до момента, пока все горутины из группы не исполнятся
	fmt.Println("hello from main!")
	// какой то код после
}
```
2) **chan** - каналы дают нам возможность передавать сигналы или информацию между горутинами.</br>
   Мы можем параметризовать канал любым типом для дальнейшей передачи по каналу экземпляров структур.</br>
   Каналы бывают небуферизированные и буферизированные, о последних чуть позже.</br> </br>
   **Создание канала:**</br>
   **ch := make(chan int)** // небуферизированный </br>
   **ch := make(chan int, 100)** // буферизированный, с размером 100 </br></br>
   Операции чтения и записи в канал являются блокирующими.</br>
   Это означает, что горутина, которая читает или пишет в канал, блокируется до момента, пока другая горутина</br>
   не запишет или прочитает в этот канал соответственно.</br>
   Вот тут и появляется разница между небуферизированными и буферизированными каналами - </br>
   запись в буферизированный канал не блокирует пишущую горутину, пока канал не заполнится до своего <b>максимального размера.</b></br>
   Операция чтения на буферизированном канале является жадной.</br>
   Таким образом, как только операция чтения началась, она не будет завершена до полного опустошения буфера.</br>
   Это означает, что горутина будет считывать буфер канала без блокировки до тех пор, пока буфер не станет пустым.</br></br>
   **Операция записи в канал:**</br>
   **ch <- struct{}{}** // записываем в канал пустую структуру</br></br>
   **Операция чтения из канала:**</br>
   **<-ch** // чтение без присвоения результата</br>
   **result := <-ch** // чтение с присвоением только сигнала</br>
   **result, ok := <-ch** // чтение с присвоением сигнала и успеха операции</br></br>
   **Deadlock** (Взаимная блокировка) - так как операции над каналами блокирующие, то мы можем организовать себе взаимную блокироку.</br>
   Если свободные горутины отсутствуют (все находятся в ожидании событий), то планировщику будет некуда передать управление </br>
   и наша программа встретит deadlock.</br>
   Самый простой пример такой ситуации:
```go
package main

import "fmt"

func main() {
    c := make(chan string)
    c <- "deadlock" // deadlocked here
    fmt.Println("hello from main!")
}
```
Еще каналы можно "закрывать" с помощью встроенной функции <b>close</b>.</br>
В таком случае при чтении из закрытого канала мы получим <b>default</b> значение типа, которым параметризован канал,</br>
а в случае записи - <b>panic</b>, так как запись в закрытый канал невозможна.</br>
Итак, изменим наш изначальный пример:
```go
	// какой то код до
	doneCh := make(chan struct{}) // создадим экземпляр канала, параметризованного пустой структурой
	go func() {
		fmt.Println("hello from goroutine!")
		close(doneCh) // отправляем сигнал
		// doneCh <- struct{}{} // отправляем сигнал, опциональный вариант, более христоматийный выше
	}()
	<-doneCh // заблокируем main-горутину до момента, пока не получим сигнал от дочерней
	fmt.Println("hello from main!")
	// какой то код после
```
Таким образом мы рассмотрели возможности синхронизации, а в частности управления порядком исполнения горутин.</br>

## Тесты
В ходе разработки программы важно не только написать сам код, но и убедиться в том, что он работает корректно, согласно требованиям.</br>
Конечно, можно просто запустить программу и проверить ее функциональность.</br>
Но такой способ не является достаточно надежным и сильно зависит от человеческого фактора.</br>
В данном разделе мы коснемся одного из способов тестирования кода - юнит-тестирования.</br>
Для написания юнит-тестов мы воспользуемся встроенным пакетом testing и для проверки результатов будем использовать внешний пакет assert.</br>
Команда установки внешнего пакета - <b>go get -u github.com/stretchr/testify/assert</b></br></br>

Например, проверим функцию Sum():
```go
func Sum(a, b int) int {
	return a + b
}
```

Создадим файл sum_test.go
(в Го тесты принято содержать в файлах с постфиксом _test.go а сами функции тестов называть с префикса Test)
и в нем напишем вот такой тест:

```go
func TestSum(t *testing.T) {
    res := Sum(1, 2)
    want := 3
    assert.Equal(t, want, res)
}
```

При запуске теста, в терминале мы увидим "PASS", а значит тест прошел успешно.
